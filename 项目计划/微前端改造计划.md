# 微前端改造计划文档

## 1. 背景与目标

本计划旨在将当前 `ai-工作流` 项目改造成基于 [无界 (Wujie)](https://wujie-micro.github.io/doc/) 的微前端子应用模块。
根据需求，我们将调整项目结构：
- 使用 `src` 目录承载微前端子应用的业务逻辑和入口。
- 保持 `components` 目录独立，作为基础组件库，不混入业务逻辑。
- 保持对现有功能的最小侵入，利用无界"几乎不用改造"的特性。

## 2. 目录结构调整

当前项目结构较为扁平，入口文件混杂在根目录。我们将进行以下调整，使其符合 "src 承载微前端" 的架构：

### 2.1 文件移动
将以下文件从根目录移动到 `src/` 目录下：
- `index.tsx` -> `src/index.tsx` (应用入口)
- `App.tsx` -> `src/App.tsx` (根组件)
- `index.css` -> `src/index.css` (全局样式)
- `App.css` (如果存在) -> `src/App.css`

### 2.2 调整后的结构示意
```
/
├── components/           # 独立组件库 (保持在根目录)
│   └── Workflow/
├── src/                  # 微前端子应用主目录
│   ├── api/              # API 请求
│   ├── index.tsx         # [移动] 入口文件 (导出生命周期)
│   ├── App.tsx           # [移动] 根组件
│   └── index.css         # [移动] 全局样式
├── index.html            # Vite 入口 HTML (需修改引用路径)
├── vite.config.ts        # Vite 配置 (需支持跨域)
└── package.json
```

## 3. 核心改造步骤

### 3.1 修改入口 HTML (`index.html`)
由于入口文件移动到了 `src`，需要更新 `index.html` 中的引用路径：

```html
<!-- 修改前 -->
<script type="module" src="/index.tsx"></script>

<!-- 修改后 -->
<script type="module" src="/src/index.tsx"></script>
```

### 3.2 改造入口文件 (`src/index.tsx`)
为了适配无界微前端，建议在入口文件中导出生命周期钩子，并支持独立运行和微前端模式运行。

```tsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import './index.css';
import App from './App';

let root: ReactDOM.Root | null = null;

// 渲染函数
function render(props: any) {
  const container = document.getElementById('root');
  if (!container) return;
  
  root = ReactDOM.createRoot(container);
  root.render(
    <React.StrictMode>
      <App />
    </React.StrictMode>
  );
}

// 销毁函数
function destroy() {
  if (root) {
    root.unmount();
    root = null;
  }
}

// 独立运行时直接渲染
if (!window.__POWERED_BY_WUJIE__) {
  render({});
}

// 导出无界生命周期钩子
export async function mount(props: any) {
  render(props);
}

export async function unmount(props: any) {
  destroy();
}

export async function update(props: any) {
  console.log('update props', props);
}
```
*注：需要在 `src/types/global.d.ts` 或类似文件中声明 `Window` 接口包含 `__POWERED_BY_WUJIE__` 属性，以避免 TS 报错。*

### 3.3 配置 Vite (`vite.config.ts`)
微前端子应用在开发环境下需要支持跨域访问，以便主应用加载。

```typescript
export default defineConfig(({ mode }) => {
  // ... 其他配置
  return {
    server: {
      port: 3000,
      host: '0.0.0.0',
      cors: true, // 允许跨域
      headers: {
        'Access-Control-Allow-Origin': '*', // 确保资源可被主应用加载
      },
    },
    resolve: {
      alias: {
        // 保持 @ 指向根目录，这样移动到 src 下的代码依然可以通过 @/components 引用组件
        '@': path.resolve(__dirname, '.'), 
      },
    },
    // ...
  }
})
```

## 4. Components 独立性说明

- **物理分离**：`components` 目录位于项目根目录，与 `src` (业务应用) 平级。这意味着 `components` 中的代码不应包含任何业务特定的逻辑（如路由跳转、特定的 API 调用等），而应保持纯粹的 UI 展示和回调。
- **引用方式**：`src` 下的业务代码通过 `import { ... } from '@/components/...'` 引用组件。
- **未来扩展**：如果未来需要将 `components` 发布为独立的 npm 包，只需将其移入 `packages/components` (Monorepo 结构) 并配置 `package.json` 即可，目前的目录结构已经为这种拆分做好了准备。

## 5. 实施计划

1.  **执行文件移动**：将 `index.tsx`, `App.tsx`, `index.css` 移入 `src`。
2.  **修正引用**：检查并修复移动后可能产生的相对路径引用错误（由于配置了 `@` 别名，大部分引用应该不受影响）。
3.  **代码改造**：按上述 3.2 章节修改 `src/index.tsx`。
4.  **配置更新**：更新 `vite.config.ts` 和 `index.html`。
5.  **类型补充**：添加全局类型声明以支持 `window.__POWERED_BY_WUJIE__`。
6.  **验证**：运行 `pnpm run dev`，确保应用能独立启动且无报错。
