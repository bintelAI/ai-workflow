# AI 工作流后端架构设计文档

本文档描述了基于 Node.js 的 AI 工作流后端架构设计。该设计遵循“代码简洁之道”，并应用了多种设计模式以确保系统的可扩展性和可维护性。

## 1. 核心目标
- **高可扩展性**：能够轻松添加新的节点类型。
- **高性能**：支持高并发的节点执行（如并行循环）。
- **健壮性**：完善的错误处理和执行日志追踪。
- **灵活性**：支持复杂的变量引用和条件逻辑。

## 2. 系统架构概览

### 2.1 核心组件
- **WorkflowEngine (工作流引擎)**: 核心控制器，负责管理工作流的生命周期、状态转换和执行调度。
- **NodeExecutorFactory (节点执行器工厂)**: 根据节点类型创建相应的执行逻辑。
- **ContextManager (上下文管理器)**: 管理执行过程中的变量作用域（Payload, Steps, Nodes, Loop）。
- **ExpressionEvaluator (表达式求值器)**: 安全地解析和计算条件表达式及变量替换。

### 2.2 逻辑分层
1. **API 层 (Express/Fastify)**: 提供 RESTful 接口，处理请求验证和响应。
2. **Service 层**: 业务逻辑处理，包括工作流定义管理、执行触发等。
3. **Domain 层 (Engine)**: 核心引擎逻辑，不依赖具体框架。
4. **Infrastructure 层**: 数据库访问 (TypeORM/Prisma)、外部 API 调用 (LLM, HTTP Client)、日志记录。

## 3. 设计模式应用

### 3.1 策略模式 (Strategy Pattern)
用于处理不同类型的节点执行。
- `BaseNodeExecutor`: 抽象基类或接口。
- `LLMNodeExecutor`, `SQLNodeExecutor`, `HttpNodeExecutor`: 具体实现。

### 3.2 工厂模式 (Factory Pattern)
用于根据节点类型动态创建执行器。
- `NodeExecutorFactory`: 根据 `node.type` 返回对应的 `BaseNodeExecutor` 实例。

### 3.3 单例模式 (Singleton Pattern)
用于全局共享的服务。
- `WorkflowEngine`: 确保全局只有一个引擎实例处理调度。
- `ConfigManager`: 全局配置管理。

### 3.4 观察者模式 (Observer Pattern)
用于执行日志和监控。
- 节点执行状态变更时通知日志服务记录轨迹。

## 4. 数据模型设计

### 4.1 WorkflowDefinition (工作流定义)
```json
{
  "id": "string",
  "name": "string",
  "nodes": [],
  "edges": [],
  "metadata": {}
}
```

### 4.2 WorkflowExecution (工作流执行记录)
```json
{
  "id": "string",

  "status": "running | success | failed",
  "context": {},
  "logs": [],
  "startTime": "datetime",
  "endTime": "datetime"
}
```

## 5. 关键流程设计

### 5.1 执行流程
1. 接收触发请求 -> 加载 `WorkflowDefinition`。
2. 初始化 `ContextManager`。
3. 寻找 `START` 节点并加入待执行队列。
4. **循环执行**:
   - 从队列取出节点。
   - `NodeExecutorFactory` 创建执行器。
   - 执行器通过 `ContextManager` 获取变量，执行业务逻辑，返回输出。
   - `ContextManager` 更新状态。
   - 根据 `edges` 寻找后续节点并加入队列。
5. 所有节点执行完毕或遇到 `END` 节点 -> 保存结果 -> 返回响应。

### 5.2 变量解析
支持 `{{nodeId.output.path}}` 语法的解析，使用正则表达式结合递归路径查找实现。

## 7. 核心类结构设计 (Conceptual)

### 7.1 NodeExecutor (策略模式)
```typescript
// src/engine/executors/BaseNodeExecutor.ts
export abstract class BaseNodeExecutor {
  abstract execute(node: WorkflowNode, context: ContextManager): Promise<NodeOutput>;
}

// src/engine/executors/LLMNodeExecutor.ts
export class LLMNodeExecutor extends BaseNodeExecutor {
  async execute(node: WorkflowNode, context: ContextManager): Promise<NodeOutput> {
    const prompt = context.resolveTemplate(node.data.config.prompt);
    // 调用 LLM 服务...
    return { text: "AI Response", usage: { tokens: 100 } };
  }
}
```

### 7.2 NodeExecutorFactory (工厂模式)
```typescript
// src/engine/NodeExecutorFactory.ts
export class NodeExecutorFactory {
  static getExecutor(type: WorkflowNodeType): BaseNodeExecutor {
    switch (type) {
      case WorkflowNodeType.LLM:
        return new LLMNodeExecutor();
      case WorkflowNodeType.API_CALL:
        return new ApiCallNodeExecutor();
      // ... 其他类型
      default:
        throw new Error(`Unsupported node type: ${type}`);
    }
  }
}
```

### 7.3 WorkflowEngine (单例模式 & 核心逻辑)
```typescript
// src/engine/WorkflowEngine.ts
export class WorkflowEngine {
  private static instance: WorkflowEngine;

  private constructor() {}

  public static getInstance(): WorkflowEngine {
    if (!WorkflowEngine.instance) {
      WorkflowEngine.instance = new WorkflowEngine();
    }
    return WorkflowEngine.instance;
  }

  async run(workflow: WorkflowDefinition, initialPayload: any) {
    const context = new ContextManager(initialPayload);
    const queue = [this.findStartNode(workflow)];
    
    while (queue.length > 0) {
      const node = queue.shift();
      const executor = NodeExecutorFactory.getExecutor(node.type);
      const output = await executor.execute(node, context);
      context.updateNodeOutput(node.id, output);
      
      const nextNodes = this.getNextNodes(workflow, node.id, context);
      queue.push(...nextNodes);
    }
    
    return context.getFullContext();
  }
}
```
